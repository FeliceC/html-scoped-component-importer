📬Event bus with a queue

Components talk without importing each other: one emits a named event, others listen to it. If an event is emitted while nobody listens yet (for example a component that loads later), it waits in a queue instead of being lost.

👉 Add a few products while the listener is offline: they pile up in the queue. Press Connect listener and they are delivered in order. Disconnect and try again.

    How to use it

    1. Create one bus and share it. Either export it from a module, or use the one every dispatcher already has: dispatcher.events.

      // shared.ts
import { EventBus } from 'html-scoped-component-importer';

export const events = new EventBus();

    2. Emit from any component with an event name and a payload.

      // components/ProductList.ts
button.addEventListener('click', () => {
  events.emit('notify', `${product.name} added to the cart`);
});

    3. Listen in another component. on() returns an unsubscribe function: call it in _destroy() so a removed component stops listening.

      // components/NotificationCenter.ts
export default class NotificationCenter {
  private readonly unsubscribe: () => void;

  constructor(element: HTMLElement) {
    this.unsubscribe = events.on<string>('notify', message => showToast(message));
  }

  _destroy() {
    this.unsubscribe();
  }
}

    Queue rules

    • ⏳ An event is queued only when its name has no listener; otherwise it is delivered immediately.
    • 🥇 Queued events go to the first listener that subscribes to that name, in emit order, then leave the queue.
    • 🧺 At most 50 events per name are kept (oldest dropped first): new EventBus({ maximumQueuedPerEvent: 20 }).
    • 🔭 Inspect it with events.queuedEvents or events.onQueueChange(queued => …), which is how the queue above is drawn.

    🛒Shared state

    A SharedState holds one object that several components read and update. Every change notifies the subscribers, so the badge below re-renders by itself when the product buttons above add to the cart.

    Subscriber

    Current state

    How to use it

    1. Create the state once with its initial value and share it (a module export, or dispatcher.createState('cart', …) to get its changes in the log).

      // shared.ts
import { SharedState } from 'html-scoped-component-importer';

export const cartState = new SharedState({ items: [] as Product[] });

    2. Update with set(): pass the changed keys, or a function of the current state. Changes are shallow-merged and the state is frozen, so never mutate it directly.

      // components/ProductList.ts
cartState.set(current => ({ items: [...current.items, product] }));

// anywhere
cartState.set({ items: [] });

    3. Read and subscribe: get() returns the current value, subscribe() calls you with the next and previous state and returns an unsubscribe function for _destroy().

      // components/CartBadge.ts
const render = () => {
  element.textContent = `🛒 ${cartState.get().items.length} item(s)`;
};
render();
this.unsubscribe = cartState.subscribe(render);

    ⚡Async mode

    The dispatcher resolves COMPONENTS/Greeting with a dynamic import(): webpack ships it as its own chunk, fetched only when the element exists.

    <div data-component="Greeting"></div>
    const dispatcher = new ComponentDispatcher();
await dispatcher.importAsyncComponents();

    🕒Sync mode with a custom selector

    A second dispatcher uses an explicit registry and its own attribute. No dynamic import, so it works with any bundler.

    <span data-sync-component="Clock"></span>
    const dispatcher = new ComponentDispatcher();
dispatcher.Selector = '[data-sync-component]';
await dispatcher.importComponents({ Clock });

    🎛️Several components, options from data attributes

    Counter reads its start value and step from data-option-*; Highlight decorates the same element.

    <div data-component="Counter, Highlight"
     data-option-start="10" data-option-step="5"></div>

    👀Observing DOM changes

    With observeDomChanges() new elements are mounted automatically and removed ones get _destroy(). Watch the log.

    const stopObserving = dispatcher.observeDomChanges();

    💥Error overlay

    A component that throws does not break the others. In development builds it is replaced by an overlay with the stack trace.
